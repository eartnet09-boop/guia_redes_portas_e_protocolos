# Portas web e DevOps

| Porta → protocolo(s) → serviço | Risco | Vetor comum | Verificação Blue Team | Ação defensiva |
|---|---|---|---|---|
| **80/TCP → HTTP** (Hypertext Transfer Protocol), **443/TCP → HTTPS** (HTTP Secure); **443/UDP → QUIC** (Quick UDP Internet Connections) em alguns serviços | Alto por exposição necessária; não é risco por si só | Falhas de aplicação, autenticação, configuração TLS (Transport Layer Security), proxy e APIs (interfaces de programação de aplicações) | `ss -lntp '( sport = :80 or sport = :443 )'`; revisar proxy e logs | Manter aplicação e proxy corrigidos, TLS moderno, HSTS (HTTP Strict Transport Security) conforme arquitetura, WAF (Web Application Firewall, firewall de aplicação web) como camada complementar, logs com request ID. |
| **3000–3002/TCP → frequentemente HTTP** → servidores de desenvolvimento Node.js/React | Alto se acessível fora do ambiente de desenvolvimento | Console/debug exposto, segredo em ambiente, dependência vulnerável ou configuração insegura. CVE (Common Vulnerabilities and Exposures)-2025-55182 afeta React Server Components em versões/configurações vulneráveis; não é definida por usar estas portas. | `ss -lntp '( sport = :3000 or sport = :3001 or sport = :3002 )'`; conferir bind e ambiente | Não publicar dev server; bind local, autenticação no ambiente, dependências corrigidas e implantação suportada. Ver [NVD CVE-2025-55182](https://nvd.nist.gov/vuln/detail/CVE-2025-55182) e aviso do [React](https://react.dev/blog/2025/12/03/critical-security-vulnerability-in-react-server-components). |
| **8080/TCP, 8443/TCP → geralmente HTTP/HTTPS** → console, proxy ou aplicação | Alto quando contém console administrativo | Interface de administração esquecida, credenciais padrão, aplicação desatualizada ou bypass de proxy | `ss -lntp '( sport = :8080 or sport = :8443 )'` | Restringir por identidade/rede, remover console público, TLS e atualização; confirmar serviço real. |
| **9200/TCP → HTTP/HTTPS** → Elasticsearch API (interface de programação de aplicações) | Crítico se sem autenticação ou exposto | Consulta, alteração ou remoção indevida de índices; abuso de API e dados | `ss -lntp '( sport = :9200 )'`; revisar autenticação, TLS, bind e políticas | Ativar controles de acesso, TLS, rede privada, menor privilégio e snapshots protegidos. |
| **2375/TCP → HTTP sem TLS por convenção; 2376/TCP → Docker API com TLS por convenção** | Crítico se daemon remoto acessível | Controle do daemon pode equivaler a controle elevado do host; credenciais/certificados mal protegidos | `ss -lntp '( sport = :2375 or sport = :2376 )'`; revisar `daemon.json` e unidades | Não publicar 2375; preferir socket local/contexto seguro, TLS mútuo se remoto, autorização, segmentação e proteção das chaves. |
| **6443/TCP → HTTPS** → API Kubernetes (orquestrador de contêineres), padrão comum | Crítico sem autenticação/autorização adequada | Abuso de credenciais, RBAC (Role-Based Access Control) excessivo, API acessível além do necessário | `ss -lntp '( sport = :6443 )'`; revisar endpoint, audit logs, RBAC e firewall | Endpoint privado, identidade forte, RBAC mínimo, audit policy, atualização e restrição de origem. |

Atribuições e portas padrão variam por implantação: confirme o listener e o processo. Uma porta não convencional não reduz por si só o risco.


**Ação prática:** diferencie ambientes dev, staging e produção; faça inventário de listeners e remova consoles/APIs administrativas da exposição pública. Consulte [hardening](../seguranca-e-defesa/hardening-de-portas.md).
